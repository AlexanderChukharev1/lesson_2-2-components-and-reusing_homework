В полном примере лекции вход, событие и lifecycle находятся в `demo/src/components/booking-card.ts`, работа со списками в `demo/src/main.ts`. Здесь событие другое: **`booking-status-request`**, а подтверждённая кнопка запрашивает обратный переход. Старый обработчик, который запрещает действие при `confirmed`, переносить нельзя.

`import type` не выполняет регистрацию. Для регистрации браузер должен выполнить модуль с `customElements.define`. Приведение `as BookingCard` тоже не регистрирует элемент.

Событие в этом ДЗ отправляется от host. `bubbles: true` позволяет контейнеру списков его получить; пересекать границу из внутреннего узла событию не нужно. Снятие слушателя требует той же функции, что была подключена. Отсутствие дублей после возврата само по себе не доказывает снятие: поэтому стенд отдельно вызывает кнопку отключённого элемента.

## Д1: атрибуты

Изучите [реакцию на изменение атрибутов](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_custom_elements#responding_to_attribute_changes). Поисковый запрос: `custom elements observedAttributes attributeChangedCallback boolean attribute presence`.

Нужно объявить наблюдаемые имена и реагировать на добавление, изменение и удаление атрибута. Для нашей задачи `compact` означает наличие, не строковое значение. Обработчик может сработать до передачи `booking`; пустое состояние тоже должно оставаться допустимым.

## Д2: слоты

Изучите [именованные слоты и запасное содержимое](https://developer.mozilla.org/en-US/docs/Web/API/Web_components/Using_templates_and_slots#adding_flexibility_with_slots). Поисковый запрос: `Web Components named slot fallback light DOM`.

Например, внутри Shadow DOM другого компонента, `info-panel`, может находиться:

```html
<slot name="heading">Без заголовка</slot>
```

Внешний код использует его так:

```html
<info-panel><h2 slot="heading">Расписание</h2></info-panel>
```

Узел `h2` остаётся снаружи, а слот определяет место его отображения. Если убрать переданный узел, виден запасной текст. Двум экземплярам нужны два разных узла: один DOM-узел нельзя одновременно поместить в два места. В нашем стенде такие узлы уже подготовлены, имя слота другое: `note`.

## Как читать диагностику

В верхнем образце счётчик слушает сам host и не скрывает повторные события. Смена данных кнопками стенда не считается событием компонента. Сравнение входного объекта помогает заметить мутацию; отсутствие мутации и отсутствие самостоятельного переключения видимого статуса проверяйте вместе.

«Дерево: то же» сравнивает shadow root и `article`, «Кнопка: та же» сравнивает сам DOM-узел. Для Д3 сначала передайте данные, чтобы кнопка стала доступна, и только затем запускайте отложенное обновление. Сохранение фокуса требуется при обновлении подключённой карточки, не при её удалении из документа.

Стенд читает `shadowRoot` для измерений. В `main.ts` такого доступа не нужно: приложение общается с компонентом через `booking` и событие.
